AMIS JSON Export Format

This document describes the JSON file produced by the JSON Export. It describes a nesting batch: the build volume, the distinct parts used, where every copy of each part is placed, and which copies could not be placed (unplaced).

All lengths are in millimetres, areas in mm², volumes in mm³ (the file itself does not store units).

1. Top-level structure

KeyTypeDescription
timestampstringExport time, local time, format YYYY-MM-DD HH:MM:SS.
batchobjectBatch-level (build volume and density) information. See section 2.
partsobjectMap of part key → part object for parts that were successfully placed in the batch.
unplaced_partsobjectOptional (only present when requested by the user). Map of part key → part object for copies that did not fit in the batch. Same schema as parts.

Keys are emitted in alphabetical order. The optional items (unplaced_parts and batch.densities) are only exported when requested by the user; consumers should treat them as empty when absent.

2. batch object

KeyTypeExampleDescription
namestring"partial_nest"Name of the batch.
box_widthnumber380.0Build volume size along X.
box_depthnumber284.0Build volume size along Y.
box_heightnumber380.0Build volume size along Z (maximum build height).
layer_heightnumber0.1Layer thickness used for slicing.
nesting_heightnumber368.71Actual height (Z extent) occupied by the nested parts; ≤ box_height.
nesting_densitynumber0.4052Fraction (0–1) of the volume up to nesting_height filled with part material.
total_densitynumber0.3931Fraction (0–1) of the entire build volume (box_width × box_depth × box_height) filled with part material. Always ≤ nesting_density.
densitiesobject{"0.10": 0.0007, …}Optional (only present when requested by the user). Density per layer height; see below.

batch.densities (optional)

Only exported when the user requests density information. It is a map from layer height to the density at that height:

  • Key: string, the height in mm along Z, formatted with two decimals (e.g. "0.10", "263.40"). Heights start at layer_height and increase in steps of layer_height up to nesting_height, so the map has about nesting_height / layer_height entries.
  • Value: number (0–1), the fraction of the build-plate cross-section filled with part material at that height. It is not cumulative: it varies per layer and is small near the top of the nest, where only a few parts remain.

Keys are strings and, like all keys, are emitted in alphabetical (lexicographic) order, not numeric order ("0.10", "0.20", …, "1.00", "1.10", …). Parse the keys as numbers and sort them if you need them in height order.

"densities": {
    "0.10": 0.000708858,
    "0.20": 0.002098776,
    "0.30": 0.003488695,
    ...
}

3. Part object (parts.* and unplaced_parts.*)

The map key (e.g. "part_4") identifies a distinct part in the batch; it equals the part_number field. Several keys may share the same name (with different scale/size).

KeyTypeDescription
part_numberstringUnique part identifier, same as the map key.
namestringName of the part (typically the source model name).
copiesintegerNumber of copies; always equals the length of instances.
instancesarray of arraysOne transformation per copy. See section 4.
box_widthnumberBounding box size along X.
box_depthnumberBounding box size along Y.
box_heightnumberBounding box size along Z.
box_areanumberVolume of the bounding box: box_width × box_depth × box_height.
surface_areanumberSurface area of the part mesh.
solid_volumenumberVolume of the solid part model.
printed_volumenumberVolume of material actually printed.

4. instances – placement transforms

Each instance is an array of 12 numbers: the top three rows of a 4×4 affine transformation matrix, in row-major order. The fourth row is implicitly [0, 0, 0, 1].

[ m00, m01, m02, tx,
  m10, m11, m12, ty,
  m20, m21, m22, tz ]

        | m00 m01 m02 tx |
   M =  | m10 m11 m12 ty |
        | m20 m21 m22 tz |
        |  0   0   0   1 |
IndexMeaning
0, 1, 2 / 4, 5, 6 / 8, 9, 103×3 rotation (and scale) part.
3, 7, 11Translation tx, ty, tz.

A point p of the part model is placed at M · [p.x, p.y, p.z, 1]ᵀ.

Placed vs. unplaced

  • parts: translations lie inside the build volume (e.g. tx=314, ty=2, tz=298, within 380 × 284 × 380).
  • unplaced_parts: the instances are laid out on a staging grid outside the build volume. Their coordinates must not be interpreted as valid positions within the batch.
